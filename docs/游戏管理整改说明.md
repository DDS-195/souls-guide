# 游戏管理整改说明

日期：2026-09-09

## 业务规则

- 游戏停用只禁止新增文章归属（新建或迁入），不下架历史文章、不清除统计。旧文章允许保留原游戏并编辑、提交审核。
- 首页默认只列启用游戏；写作和历史统计可读取包含停用游戏的列表。写作页不再假定游戏 ID 为 1，没有可用游戏时提示并禁止保存。
- 名称 trim 后必填且最多 50 字；简介为字符串，最多 500 字；状态为数值 0/1；排序为 0–2147483647 整数。封面为合法本地图片路径或 null。
- 新增默认启用、追加末尾。列表稳定按 sort_order,id 排序。排序允许部分更新，提交的每条记录必须包含版本；前端上下移提交当前列表。
- 修改、启停、删除和排序使用 version 乐观锁；任何已修改的记录返回 409，排序全部回滚。并发新增出现数据库死锁时仅重试已回滚的事务，最多三次。
- 文章写入在事务内共享锁定游戏，启停与文章新增按数据库锁确定先后顺序。
- 所有关联文章（包含草稿）都会阻止删除。管理列表显示关联数量；数据库外键仍作为最终保护。
- 删除/替换封面与清理任务登记在同一事务内；文件由现有周期清理任务处理，遇到共享引用保留任务，异常下轮重试。不会因为后置清理异常让已删除游戏返回失败。

## API 变更

- GET /api/games：include_inactive=0|1，默认 0；设置 1 返回历史游戏，公开范围仅游戏字典，无新增私密数据。
- GET /api/admin/games：仍返回数组，增加 version、post_count。
- PUT /api/games/{id}：必须携带 version，并至少一个修改字段；启停前端仅提交 status、version。
- DELETE /api/games/{id}：body 必须包含 version。
- PUT /api/games/sort：1–1000 项数组，每项 {id,sort_order,version}，不允许重复 ID、错误类型或不存在的 ID。
- 参数错误返回 400，不存在返回 404，版本冲突返回 409。

## 发布与兼容

新增迁移 007_game_versions，给既有游戏补 version=1 并建立 game_cover_cleanup。保留原名称、状态和排序；通过服务启动或 npm run db:migrate 执行。前后端同步发布，旧页面无版本号的写请求会被拒绝，刷新后重试。

## 界面及测试

管理页改为卡片，完整显示名称和简介，窄屏操作换行。复用统一弹窗、加载/空态/错误组件；请求期间禁用操作，首尾排序按钮禁用；冲突不会自动更新弹窗版本后强制覆盖。

新增 12-games-lifecycle.suite.js，覆盖参数、旧版本启停、停用关联、排序原子性、默认追加、版本删除和清理队列；原游戏测试补充版本字段。测试在独立测试库运行，不更改真实游戏数据。
