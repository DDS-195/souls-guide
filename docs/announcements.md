# 公告管理领域契约

## 职责边界

公告用于全站展示一条当前有效信息；系统通知用于向一个或多个用户的通知中心投递消息。二者是独立功能和独立管理页面，发布公告不会隐式群发通知。

## 状态机

```text
create / clone -> draft -> published -> archived
                    |
                    -> deleted（软删除，仅草稿允许）
```

- 只有 `draft` 可以编辑、发布或删除。
- `published` 和 `archived` 是冻结版本；需要修订时复制为新的 `draft`。
- 只有当前全局发布槽指向的 `published` 公告可以归档。
- 发布新草稿时，旧的当前公告在同一事务中归档。

`announcement_channels.global` 是所有发布操作的固定锁入口和公开读取的唯一事实源。它避免不同目标公告并发发布时采用不同加锁顺序。`announcement_events` 与业务变化在同一事务内写入完整快照；通用 `operation_logs` 继续记录 HTTP 层操作信息。

`004_announcement_lifecycle` 迁移前的公告只有通用操作日志，没有可靠的逐版本正文快照；迁移不会伪造历史事件。事务快照从迁移上线后的第一次创建、修改或状态迁移开始完整记录。

## 版本与已读

草稿更新使用 `version` 乐观锁。客户端必须提交当前版本，陈旧版本返回 `409`。发布版本不可原地修改。

登录用户的已读状态存入 `announcement_reads`，主键包含公告 ID 和版本；游客使用浏览器本地 `id:version` 键，最多保留 100 条并容忍损坏存储。公开弹窗每五分钟、窗口重新获得焦点或页面重新可见时检查一次当前公告。

## 错误语义

- 输入类型、空白内容、长度或版本非法：`400`。
- 公告不存在或已软删除：`404`。
- 乐观锁冲突或状态迁移非法：`409`。
- 未登录或非管理员访问管理接口：`401/403`。

完整请求和响应字段见 [`openapi.json`](./openapi.json)。
