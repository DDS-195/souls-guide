# 攻略体验第二阶段：个人攻略入口

## 实现范围

- 我的收藏支持按游戏筛选；筛选状态写入 URL，切换筛选重置分页。
- 我的关注保留原入口，通过“关注作者 / 最新攻略”切换；攻略视图支持游戏筛选。
- 动态是当前关注作者的已发布攻略，包含关注前的历史内容，不是推荐或未读消息。按首次发布时间及文章 ID 倒序。
- 收藏按收藏时间及收藏记录 ID 倒序，包含停用游戏的历史已发布文章。
- 私有列表身份只取后端鉴权用户，不接受客户端指定其他用户。
- 复用公开攻略摘要查询，补齐游戏名称、作者昵称、标签，去掉收藏列表的完整正文；列表与总数在同一事务快照读取。
- 每页默认 10 篇，上限 50；仅预加载首屏封面。切换筛选/视图取消旧请求并丢弃过期响应。
- 手机一列、平板两列、宽屏三列，筛选与数量、刷新在同一行。错误重试、空状态与加载状态分别展示。

## 契约与兼容

`GET /api/favorites` 新增可选 `game_id`，分页结构保持不变，返回摘要而不是正文。

`GET /api/following-feed` 需要登录，支持 `game_id/page/pageSize`；不改变关注关系、通知、文章发布状态。

前端仍使用 `/me/following`，攻略视图为 `?view=posts`，游戏筛选为 `?game=编号`。

## 尚未实施

手机可视化编辑器与“已发布文章修改期间保留原公开版本”单独推进。后一项需要同时处理审核、公开列表、媒体访问及统计归属，不能只调整详情页状态判断。HTTP 保持现状，未更改历史攻略正文或用户关系。

## 分页边界

本阶段保留项目现有的 offset 分页。同一排序时间以 ID 打破平局；跨页期间出现新收藏/新发布或取消关系，列表可能移动，刷新会重新加载。不是跨请求固定快照，也不宣称任意实时变更下分页无重复。
