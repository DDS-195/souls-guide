# 攻略体验第三阶段：双端可视化写作

## 本轮范围

手机正文不再降级为 HTML 源码 textarea，而是复用项目已有 TinyMCE 可视化编辑器。没有引入新的编辑器依赖，没有改动文章、审核、媒体归属接口或数据库。

- 移动设备采用简化工具栏，支持撤销重做、段落/标题、粗体斜体、列表、图片、链接及全屏。原生手机工具栏横向滚动；桌面缩窗时由“更多”展开隐藏工具。
- 手机和桌面使用同一组件实例，宽度改变不会卸载编辑器；正文、选区和上传不因断点变化被重新初始化。
- 编辑器正文和窄屏弹窗输入字号为 16px；限制编辑器宽度，窄屏非全屏高度为 400px。
- 图片使用编辑器上传页签选择设备文件，沿用 1920px / 0.8 压缩和现有上传接口。图片处理中阻止保存或提交，多图片上传直到全部结束才解除 busy。
- 编辑器初始化之前禁止保存；模块加载失败自动重试一次，失败后显示错误和重新加载入口，已有表单继续保留并按原逻辑暂存本机。
- 继续保留本机草稿恢复、创建幂等、文章版本冲突、离开提示和视频分片上传。

## 性能取舍

TinyMCE 仍仅在进入写作页后异步加载，首页及列表不直接加载编辑器。但与原来的手机 textarea 相比，手机首次进入写作页会额外下载完整编辑器包（当前 gzip 约 437KB，另有样式）。这是可视化能力的实际成本，本轮不宣称写作页首开更快。后续如网络实测不理想，应评估更小的编辑器或拆分非必要插件，不能通过隐藏构建警告声称已优化。

## 验收

前端自动测试新增：编辑器未初始化的保存阻止、正文图片上传期间的保存阻止、多图片并发 busy、失败释放和卸载后的过期回调隔离。

隔离浏览器验收已确认：正文输入、粗体、设备文件选择及上传回填、图片插入、失败保存时保留内容，以及重新打开后恢复图文草稿。390px 窄屏没有横向溢出，正文实际字号为 16px；变更为桌面宽度后 iframe ID 与图文内容不变。

文件选择自动化曾耗时较长，不将其耗时作为产品上传性能测量。浏览器仅进行桌面引擎的窄屏验收，不能替代 iOS Safari / Android Chrome 真机软键盘、触摸滚动和相册验证。

2026-10-01 最终验收结果：

- 前端 5 组自动测试全部通过；TypeScript 检查及生产构建通过。ESLint 为 0 错误，仍有 1 条原有的通知广播组件属性顺序警告。
- 服务器独立测试数据库回归 246 项通过、0 项失败；测试数据库及测试数据已清理，不在生产库执行测试写入。
- 320px 和 390px 窄屏均无横向溢出；切换至桌面宽度后编辑器实例与图文内容保持不变。验收截图保存在项目外的 souls-guide文档/验收与测试记录/手机可视化写作验收-20261001.png。
- 仅更新 Nginx 前端容器，后端镜像、数据库和 HTTP 部署方式不变。旧前端镜像标记为 soulsguide-nginx:pre-mobile-editor-20261001，源文件备份保存在 /opt/soulsguide-mobile-editor-20261001/source-before.tgz。
- 上线后源文件核对无差异，后端健康；首页、游戏接口、文章接口返回 200。线上首页、写作页脚本及编辑器脚本指纹与构建结果一致，写作路由和中文语言资源正常。

现存构建提醒仍包括 TinyMCE 大包与 API 模块混合静态/动态导入；本轮没有宣称消除这些性能问题。真机软键盘、相册和触摸交互尚未验收。

## 后续独立阶段

已发布文章修改待审期间保留原公开版本尚未实施。该改动必须统一审核、文章列表、详情、收藏/关注、媒体访问及统计归属；本轮仍沿用原有待审期间暂停公开访问规则。
