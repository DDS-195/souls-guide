# 通知中心整改说明

## 行为与接口

- 前台统一维护未读数量：登录、窗口恢复焦点、前台每30秒刷新；退出清零，旧请求不覆盖新会话。不是实时推送。
- 分页查询支持类型筛选；同一事务读取列表、总数、未读概况。新增只读 summary 与 target 接口，全部按当前接收人隔离。
- 批量已读提交查询响应 cutoff_id，并可指定类型；截止编号之后的新消息保持未读。旧客户端省略截止编号时，在服务端执行请求时取边界。
- 单条已读不立即移走背景条目；切换筛选或刷新时重新归类。弹窗支持明确关闭、Escape、焦点恢复及长内容滚动。
- 审核消息与系统通知正确标识，显示北京时间，历史被注销的发送人使用明确占位。
- 新互动/文章审核通知保存文章标题快照；评论、回复保存新增评论编号。旧消息不伪造历史快照，文章尚存时仅回退当前标题。
- 跳转前重新检查目标。已删除评论可退回文章；文章不可访问时保留通知但不跳转。评论按每页20个根评论计算位置；并发新增/删除可能使位置改变，页面给出提示。
- 点赞、关注同发送人、接收人、对象在十分钟内只提醒一次，业务互动计数不受影响；评论和回复不按此规则抑制。

## 容量与边界

新增接收人/时间排序索引及去重索引。仍使用分页与精确总数，未做百万级压力测试，不宣称无限容量。
本次不自动删除数据库通知；建议先依据实际增长率确定已读通知在线保留期，再建设批量归档校验流程。不能未经确认丢弃未读或重要审核结果。
十分钟去重不是全站反滥用系统，评论灌水、异常账号行为需额外统一限流治理。用户查阅通知会改变已读状态，浏览器验证应优先使用已读通知或隔离账号。

数据库变更为011_notification_center；历史通知保留。
