## 结论与范围

没有发现近期攻略体验、个人动态、手机富文本改动造成站点整体失效或前后端契约断裂的证据。线上主链路可用，源码与运行版本一致，但不等于不存在 bug。

本轮确认 11 类功能/可靠性问题，另有依赖安全告警及容量、性能债务。最高优先级是仍对外开放的旧媒体删除入口绕过文章版本和审核规则。其余主要集中在异步请求乱序、用户资料恢复、统计口径及运维故障恢复。不能将这些问题全部归因于本次手机编辑器修改。

本轮只审计：未修改业务源码、未发布新镜像、未改 HTTP 配置。生产验证使用读取接口和查询；写入型回归在独立测试库、临时上传及日志目录执行，未向线上社区发布测试内容。复现中的 VM 为实际函数/组件脚本配合模拟数据库或请求，不等同于全流程真机验收。

## 问题清单（建议修复顺序）

### 1. P1：独立媒体删除绕过文章版本与审核

位置：[mediaController.js:78](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/controllers/mediaController.js:78)、[mediaService.js:45](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/services/mediaService.js:45)、[adminService.js:42](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/services/adminService.js:42)。

`DELETE /api/media/:id` 仅验证作者/admin，删除 media 行与对应 post_assets，不锁文章、不递增 content_version、不更新发布状态，也不修正正文及视频时间点。

实际函数 + 模拟 DB 复现：管理员已预览待审 v4 的视频，作者调用独立删除后版本仍为 v4，旧版本审批仍成功，而落库快照已变成没有视频。已发布正文图片也可被独立解绑，正文 img 仍在、状态与版本不变；无其他公共引用时游客访问会被媒体鉴权拒绝，之后资产还可过期回收。不是立即物理删盘。

前端目前只声明 mediaApi.remove，没有视图调用；属于潜伏 API 一致性缺陷，不是本轮普通写作 UI 已经必然触发。现有媒体测试只检查草稿视频删除及延迟回收。

修复：废止旧入口或统一进入文章更新事务，使用同一行锁、版本校验、状态机、媒体/正文/概况同步更新。不能只追加版本自增。补测预览后移除媒体导致旧版本审核 409、公开图片引用、视频时间点清理。

### 2. P2：封面并发上传提前解锁、旧响应覆盖新选择

位置：[Write.vue:197](C:/Users/86195/Desktop/全栈学习/souls-guide/client/src/views/creator/Write.vue:197)。

先选 A、再选 B；B 先完成就把 coverUploading 设为 false，A 仍在处理中却允许保存。A 后到会覆盖 B，并尝试回收 B 的临时资产。实际组件脚本 VM 已复现 busy=false、保存创建请求使用 B、随后封面变 A。后端会拒绝删除已绑定的 B，不能声称已发布封面必然误删。

修复：封面上传串行或采用 latest-request + 活跃任务计数；明确替换、移除、卸载及账号变化的失效规则。补测两次上传乱序、失败及移除期间旧响应返回。最近富文本正文图片已有计数保护，不应混为同一个问题。

### 3. P2：登录资料补拉失败后出现假空列表与草稿保护缺失

位置：[Login.vue:29](C:/Users/86195/Desktop/全栈学习/souls-guide/client/src/views/Login.vue:29)、[router/index.ts:86](C:/Users/86195/Desktop/全栈学习/souls-guide/client/src/router/index.ts:86)、[MyLists.vue:103](C:/Users/86195/Desktop/全栈学习/souls-guide/client/src/views/MyLists.vue:103)。

登录返回 token 后，/users/me 若临时失败，fallback 只记录 username/role，没有 id；守卫见 userInfo 对象存在就不再补拉。列表因 uid 缺失直接返回，既不请求也不报错。VM 已确认收藏请求次数 0、列表数 0。此状态进入写作时 storageKey 为空，本机草稿无法保存。

修复：区分“已登录”与“完整资料就绪”；需要身份编号的页面必须补拉或明确错误重试。不能把暂时未加载当作真实空数据；写作必须具备有效用户编号后初始化账户隔离草稿。补测资料请求失败后恢复网络。

### 4. P2：举报筛选和我的作品分页被旧请求覆盖

位置：[Reports.vue:33](C:/Users/86195/Desktop/全栈学习/souls-guide/client/src/views/admin/Reports.vue:33)、[MyPosts.vue:26](C:/Users/86195/Desktop/全栈学习/souls-guide/client/src/views/creator/MyPosts.vue:26)。

### 5. P2：混合作者评论树删除导致创作者统计错误

位置：[interactService.js:227](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/services/interactService.js:227)、[analyticsService.js:72](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/services/analyticsService.js:72)。

删除整棵评论树时按总节点数记录 comment_delete，却仅根据删除操作者是否文章作者判 is_internal，未按被删评论作者逐条区分。

实际函数 + 模拟 DB 复现：作者删除自己的根评论及读者回复，两条删除全部被当作内部操作，漏记读者回复删除；读者删除自己的根评论及作者回复，只有一条有效新增却计两条有效删除，净增失真。文章 comment_count 重算正确，错的是统计事件和日聚合。

修复：操作审计保留操作者；业务删除数按原评论作者排除作者自身与已删除占位，分开记账。补测混合作者回复树及账户注销占位。历史修正须单独评估证据，不应凭当前关系表直接伪造历史。

### 6. P2：资料保存成功文案与实际保存内容不一致

### 7. P2：用户输入类型、生日边界缺失会转成 500

位置：[userController.js:16](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/controllers/userController.js:16)、[userController.js:110](C:/Users/86195/Desktop/全栈学习/souls-guide/server/src/controllers/userController.js:110)。

注册/登录未先验证 username/password 是字符串，资料也只用 length 判断，生日直接进入 SQL。实际 bcrypt + 模拟服务已确认 password 为数字、布尔或对象可穿过长度检查并抛参数异常，最终 500；非法生日有明确数据库错误路径，未在生产尝试。

修复：字段白名单、严格类型、长度和真实日期校验，非法请求返回 400；并发重复注册的唯一键异常映射为 409。现有测试仅覆盖字符串长短和合法资料。

### 8. P2：异常退出留下日志维护锁，后续清理停止

修复：具有身份、时间与并发安全的锁恢复规则，并记录长期跳过维护的异常；不能简单按固定秒数删除仍有效的活跃锁。补测强制退出/陈旧锁/两个维护者。

### 9. P2：恢复脚本未核对备份清单且提前报告完成

## 依赖审计：需要更新，但不能直接等同于可利用漏洞

镜像源 npmmirror 的 audit API 返回 404；使用显式 npm 官方 registry 只读重查，没有改变 npm 配置或执行 audit fix。

- 前端完整依赖审计：3 个被标记的软件包（axios high、brace-expansion high、dompurify low），不是 3 个已证明可利用的项目漏洞。
- 后端完整依赖审计：1 个 brace-expansion high；来自 nodemon → minimatch 开发工具链。后端 omit=dev 审计为 0 项，不能由此推断所有安全风险都不存在。
- 已装版本：axios 1.19.0、DOMPurify 3.4.13、brace-expansion 5.0.9。前端 brace-expansion 经 ESLint 进入开发依赖。
- Axios 部分告警仅限 Node HTTP/HTTP2，不能直接套到浏览器；已核对的默认 method 告警要求额外原型污染前提，项目使用 create 实例及明确 get/post/put/delete 方法，尚未证实利用链。修复版本与条件见 [维护者公告](https://github.com/axios/axios/security/advisories/GHSA-9fr6-4gfg-395g)。
- DOMPurify 此告警要求 IN_PLACE 与会移除节点的 afterSanitize hook。PostBody 使用 RETURN_DOM_FRAGMENT，未发现上述调用模式，不应声称正文已经有确定 XSS。已公告修复版本 3.4.16，见 [维护者公告](https://github.com/cure53/DOMPurify/security/advisories/GHSA-p98j-92pf-mc4p)。
- brace-expansion 递归拒绝服务告警见 [公告](https://github.com/advisories/GHSA-qhr7-859c-m2p7)；升级开发工具链也要验证锁文件和构建兼容性。

建议单独安排小范围补丁升级与锁文件更新，重跑上传/鉴权/净化和构建，不使用强制升级掩盖兼容风险。

## 不计为新 bug 的欠缺

- TinyMCE JS gzip 约 437KB，另有编辑器 CSS；只在写作页加载，但手机首开有成本。ECharts 统计 JS gzip 约 172KB。不能通过调高警告阈值声称性能已改善。
- 旧前端 hash 资源、层叠发布镜像、回滚标签与阶段源文件包没有独立保留策略。每日备份保留 14 天不会清理这些发布副本。当前未爆盘，建议设版本数量和资源宽限期，周期性从干净基础镜像重建；不得直接删所有旧资源或镜像。
- 1.6GiB 宿主在视频处理、隔离回归或服务器构建时余量有限；本轮没有进行新的压力测试，不宣称高负载容量已达标。
- 手机软键盘、触屏工具栏、相册选图和断网恢复仍需 iOS/Android 真机验证。浏览器窄屏不是完整真机适配证据。
- 已发布文章修改期间保留原公开版本仍属于独立未实施需求，当前待审暂停公开规则未被本轮改变；不计为新回归。
- 搜索仍为字面子串匹配，个人列表仍为 offset 分页；实时新增/取消关系可使跨请求分页移动，这与当前已说明边界一致。
- HTTP 按用户要求保持，不纳入本轮修改范围；它的明文传输风险没有因此消失。

## 后续验收原则
