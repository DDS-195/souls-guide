# 用户管理整改

## 账号与评论

- 封禁接口保留 PUT 路径，但必须提交明确的 status、management_version 对应的 version 和原因。过期版本返回 409，不能通过重试将封禁反转成解封。
- 封禁递增 token_version，解封不复活旧凭证。封禁不下架历史文章。
- 永久删除必须先获取影响预览，再提交完整用户名、fingerprint 和原因；状态或影响数量变化要求重新预览。管理员和公告作者不可删除。
- 账号自己发布的文章及其评论树删除（包括他人的评论）；其在其他文章发表的评论清空正文与作者关联，保留已删除占位和他人回复。占位不可单独删除，可继续回复，但不会向已删除作者发通知。
- 评论计数保持讨论节点口径，包含已删除占位，不等于仍可阅读的正文数量。历史分析事件不回写或伪造删除事件。

## 资产和记录

- 收集头像、上传资产（含未使用临时上传）、文章封面和媒体地址，事务内写 user_asset_cleanup。共享引用检查通过后后台删除文件；失败保留任务重试。
- 文件清理异步完成，不以物理文件删除结果改变账号删除事务的成功状态。定时清理默认每小时运行，启动后约五分钟首次运行。
- user_management_events 与业务操作同事务保存操作者、目标身份快照、原因、状态或删除影响；不随目标用户删除。现有通用操作日志继续保留，详细事件暂未新增独立查询页。
- 历史统计、审计及通知快照按现有策略保留，删除账号不意味着清除所有历史痕迹。尚未定义的长期保留期限需要运营另行确定。

## 页面与发布

- 支持用户名、昵称、完整 ID 搜索及角色/账号状态筛选，展示 ID，时间以北京时间显示。
- 永久删除收进“更多”，需影响预览、用户名输入和原因确认。封禁/解封均需原因和确认。
- 前后端同步发布：先 npm run db:migrate 应用 009_user_management，再重启后端。旧版无参数状态反转请求将返回 400。
- 14-user-management 专项测试覆盖并发封禁、旧凭证、删除预览变化、他人回复保留、临时资产重试、审计失败回滚与权限筛选；测试使用独立数据库。
