# 全局审计整改（2026-09-12）

## 按审计顺序处理

1. 写攻略：创建成功后保留文章 ID，提交审核失败时明确提示文章已保存；重试更新同一篇文章，不重复创建。创建请求本身响应丢失的幂等性仍需后端请求编号机制，本次不宣称覆盖该场景。
2. 编辑路由：按写作页面路径重新挂载编辑器，加载成功前禁止编辑保存，避免不同文章之间残留表单或错写目标。
3. 修改密码：当前密码错误返回 400，保留有效登录；成功修改密码仍使旧凭证失效。
4. 鉴权故障：JWT 无效与数据库故障分开处理；前端启动和路由权限恢复失败不再一律退出登录，旧请求的 401 不清理新的登录凭证。
5. 我的列表：加载更多失败回退页码，并提供错误提示和重试入口，避免跳过数据页。
6. 关注：防重复点击，校验请求序号、用户目标和登录凭证，离开页面后不再回填旧响应。
7. 浏览历史：使用账号独立存储键；登录资料尚未恢复时延迟记入该账号。旧共享历史无法确定归属，不自动迁移到任一账号，也未删除旧数据。这是应用层隔离，不是对同一浏览器本地存储的加密保护。
8. 评论状态：详情页保存各评论回复草稿、展开与分页状态，子评论重新挂载时恢复，切换文章后清理。离开文章页面后不保证草稿持久化。

另补充文章标题、正文、分类、标签、封面和视频字段的类型与边界校验，异常参数返回 400。

## 验证与边界

- 后端回归：225 PASS / 0 FAIL，包含真实 HTTP/MySQL 测试及鉴权数据库故障测试。
- 独立测试库自动销毁，测试未在开发库创建文章或发送通知。
- 前端类型检查与生产构建通过；Lint 为 0 错误、1 条已有属性顺序警告。
- 前端尚未完成浏览器逐项故障注入和跨设备回归，不将构建通过等同于所有交互场景验证完成。
- README 更新当前测试规模，OpenAPI 补充密码错误与登录失效的区别。历史专项报告保留当时的测试数量，不覆盖历史记录。
