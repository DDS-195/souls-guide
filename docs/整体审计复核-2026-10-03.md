# SoulsGuide 整体审计复核

审计日期：2026-10-03。对象：本地当前工作区（含尚未提交的修改）。

本轮包含跨模块代码审阅、前端构建与回归、独立数据库上的后端 HTTP 回归、针对性异常复现、浏览器抽查和依赖审计。未修改项目业务代码，未部署，未在生产数据库写入测试数据。历史报告中的线上测试结果仅作参考，不视为本轮重新验证。

## 结论与处理顺序

主要业务已形成较完整的实现与回归基础：权限实时校验、审核版本冲突、文章创建幂等、事务回滚、通知已读边界、媒体访问控制等均有代码与测试支撑。但仍存在一个已复现的私有视频权限缺陷，以及统计口径、前端异常处理、测试环境一致性方面的问题。

建议顺序：**私有视频权限 → 视频容量约束 → 统计口径 → 前端异常与键盘操作 → 测试环境、依赖和交付整理**。不建议在这些问题解决前继续扩大视频上传规模。

后端两项失败的区别：

1. **通知表情群发失败是测试库初始化的环境依赖问题。** 本机 MySQL 8.0.40 的默认字符集为 utf8mb3。`server/test/setupTestDatabase.js:43` 先创建不指定字符集的数据库；随后 schema 中的 `CREATE DATABASE IF NOT EXISTS ... utf8mb4` 不会修正已经存在的库。基础表继承 utf8mb3，迁移新增表采用 utf8mb4，300 个表情字符群发返回 500，日志为字符集转换失败。在一次性副本中，仅将初始建库改为明确的 utf8mb4 后，相同 HTTP 请求成功返回 200。原项目文件仍未修改。单独转换 notifications 表的对照没有解决全部混用问题，因此修复应覆盖初始化一致性，而不是只改一张表。此结论不能直接用于认定线上通知故障，线上字符集本轮未读取。
2. **真实视频上传/探测/转码用例因 `spawn ffmpeg ENOENT` 失败。** 本机 PATH 缺少 FFmpeg，未完成真实编解码链路。本轮视频权限复现使用明确跳过媒体探测的隔离测试文件，只证明权限问题，不用于证明视频格式、转码或播放性能。

测试创建的数据库已在各次运行结束销毁，登记的测试数据和媒体文件已清理。

## 已确认的问题

### A1 / P1：知道文件指纹即可认领他人的未公开视频

位置：`server/src/controllers/mediaController.js:36`、`:40`；`server/src/services/videoService.js:189`、`:221`。

完成状态查询按全局 MD5 查找结果，一旦找到 URL，就为当前请求用户登记视频资产，未验证其是否拥有原上传会话或原资产。进行中的 merge 又只以 hash 为键共享 Promise，第二个用户会跳过首个请求执行的 owner 校验。

隔离环境的实际 HTTP 结果：

```text
创作者 B 请求创作者 A 的未公开文件：404
B 提交已知 hash 查询上传状态：200，生成 B 的资产登记
B 再次请求该文件：200，字节与 A 的文件一致
两个不同 owner 同时调用 merge：得到相同的进行中 Promise
```

触发前提：B 具备创作者/管理员上传权限，并知道对应 MD5。本轮没有证明可枚举任意未知视频，问题在于把文件指纹当成了所有权凭据。MD5 去重不能替代访问授权。

建议：完成状态查询与合并都先验证 owner；上传会话按用户隔离。跨用户物理去重可以在后端保留，但不应仅凭客户端 hash 直接授予读取权。补充已完成、合并中、失败重试、私有 Range 读取的双账号回归。

### A2 / P2：互动用户率的分子、分母人群不一致

位置：`server/src/services/creatorService.js:60`、`:70`、`:77`，以及排行/分类中的同类计算；契约 `docs/analytics.md` 将其描述为“用户覆盖率”。

实际复现：一名用户产生有效阅读，两名用户点赞同一文章，接口返回 `uv=1`、`engaged_users=2`、`engagement_rate=200`。点赞接口不要求先完成阅读上报；上报失败、快速操作或跨周期行为也可能造成这种组合。匿名与登录阅读的标识还存在归属边界。

建议先明确产品口径：若称“阅读用户互动率”，分子应为同一周期、同一范围的有效阅读人群中发生互动的人数；若保留当前算法，应改成明确允许超过 100% 的比值名称并解释。不要简单把数值截断到 100%，否则会掩盖统计偏差。

### A3 / P2：注册过程可重复提交，并可能在离开页面后跳转

位置：`client/src/views/Register.vue:13`、`:41`、模板输入框的 Enter 事件。

按钮会禁用，但处理函数没有 loading 重入保护；输入框的 Enter 仍可再次调用。受控执行实际产生 2 个并发注册请求、2 次完成后的导航调用。该组件也没有页面卸载后的响应失效判断。

后端同名唯一约束能防止创建两个同名账号，因此主要影响是重复请求、成功与冲突提示争抢，以及延迟响应改变当前页面。

建议采用与登录页一致的提交锁和存活/请求序号保护，统一表单 submit 入口。

### A4 / P2：用户主页把请求失败展示成“不存在”或“没有文章”

位置：`client/src/views/UserProfile.vue:55`、`:104`。

资料请求的所有错误都进入 notFound；文章列表请求的错误被吞掉。受控注入 500 后，资料分支得到 `notFound=true`；列表分支得到 `total=0、rows=0、loading=false`，没有独立错误状态。

建议只把明确的 404 显示为不存在；网络/500 展示加载失败和重试。列表保留已有结果，首屏失败不能伪装成空列表。

### A5 / P2：浏览器存储异常可阻断用户状态初始化

位置：`client/src/stores/user.ts:11`、setToken/logout；`client/src/utils/request.ts:25`；`client/src/api/index.ts` 和公告组件还有直接存储访问。

对 localStorage.getItem 注入 SecurityError 后，实际执行用户 store 初始化会直接抛出，无法正常建立状态。写入配额或访问策略异常也缺少一致回退。并非所有浏览器隐私模式都会触发，触发条件是存储访问确实被拒绝或写入失败。

建议集中封装读写，明确内存回退与会话提示策略；不要让存储失败使公共首页也失去可用性。登录、退出和媒体凭证的会话判断需一起处理。

### A6 / P2：未知地址没有完整兜底

位置：`client/src/router/index.ts`。

浏览器打开不存在的本地路由，页面正文只有返回箭头，控制台提示 No match found，没有 404 说明和回首页入口。`/admin` 父路由还缺少默认子页/重定向（此项为代码确认，未在浏览器登录管理员复现）。

建议添加 NotFound 页面及明确返回入口，给后台根路径设置默认页，并验证直接打开、刷新及浏览器返回。

### A7 / P2：全局导航和部分入口不可通过键盘正常操作

位置：`client/src/App.vue:108`、`:300`，`client/src/views/Profile.vue:165`，`client/src/views/MyLists.vue:235`，`client/src/views/UserProfile.vue:180`，登录/注册表单。

多处导航使用只有 click 的 div；注册页浏览器检查确认 3 个输入框均没有关联 label、id、name、autocomplete。影响键盘导航、读屏及表单自动填充，不只是视觉问题。

建议页面跳转使用 router-link，操作使用 button；补齐表单标签、自动填充属性及焦点样式。首页 PostCard 的标题/作者已使用链接，文章分享/举报菜单也已有改进，不应把这些已修部分列为缺陷。

### A8 / P2：测试环境初始化依赖数据库默认字符集

位置：`server/test/setupTestDatabase.js:43`。复现与对照见测试结果部分。

建议显式创建 utf8mb4 测试库，并在测试启动时检查库、基础表和关键文本列字符集；生产发布前做只读检查，发现旧字符集后制定专门迁移，不应直接批量转换生产表。本机 FFmpeg 和证书测试依赖也应在测试说明里列明。

## 代码确认的容量与设计欠缺

以下不与上述已复现功能错误混为一谈。

1. **视频资源约束仍不完整。** `videoService.js:128` 固定 scale 目标可能放大小分辨率输入；转码等待队列没有长度/等待时限。`uploadCapacity.js:14` 在 HTTP close 时释放额度，但视频作业未同步取消，因此 HTTP 并发限制不能视为后台作业总量上限。建议只缩不放大、有界队列、明确取消或异步任务状态、磁盘空间预留。本轮未重新执行大文件/生产压力测试，也未测得当前生产峰值。
2. **统计和通知的数据生命周期尚未闭合。** 当前统计查询仍主要扫描事件事实表，日聚合已经写入但尚未全面承担查询；阅读防重、日访客集合、通知等缺少统一的归档/保留策略。不能直接删除统计事件后继续声称任意历史周期都能精确查询，需先明确保留窗口、汇总与去重语义。当前分页降低了单次渲染量，增加虚拟列表不能解决数据库持续增长。
3. **已发布文章编辑后暂时退出公开状态。** `postService.updateComplete` 将 published 改为 pending，旧公开版本不再单独提供。实现与现有审核约定一致，但玩家原链接、收藏和阅读会受修改待审影响。若希望稳定运营，应引入公开版本与待审修订版，连同媒体授权和统计归属一起设计。
4. **较重的页面依赖仍需性能预算。** 当前编辑器 JS 约 1,317KB（gzip 437KB），统计页 JS 约 504KB（gzip 172KB）。它们有路由/组件按需加载基础；不能仅凭这些数值判定首页 LCP 不合格。本轮未做新的真实手机 Web Vitals 测试。应针对写作/统计首开测量，再评估插件精简和加载时机。
5. **开发依赖告警和交付记录需要整理。** npm audit 的开发依赖链告警应跟进上游兼容修复，不应直接执行会降级 nodemon 的 force 修复。工作区有大量未提交/未跟踪文件，部分 README 和注释仍描述旧 Node 版本、旧测试数量。应形成可重建的提交、版本号和发布记录，确保部署产物对应当前源码。
