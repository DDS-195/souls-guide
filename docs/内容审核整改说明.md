# 内容审核整改说明

## 行为与边界

- 待审列表只返回队列摘要，按 submitted_at 和 id 排序；历史未知提交时间为 NULL，回退创建时间排序并在界面标明未知，不伪造提交时间。
- 点击审阅通过管理员专用 GET /api/admin/posts/:id/review 获取正文、封面、游戏、标签、媒体、内容版本及最近 20 条审核记录。详情不增加阅读量，不对游客或普通创作者开放。
- 通过和驳回均必传 content_version；驳回还须提供去空白后 1—200 个 UTF-16 单元的字符串 reason，与浏览器 maxlength 一致。非法参数返回 400，不存在返回 404，版本或状态冲突返回 409。
- 详情读取、编辑、审核围绕同一 posts 行进行加锁。保存任何内容（含标签、媒体）都会递增 content_version。已发布内容保存后进入 pending；待审内容修改后重新排队。提交草稿或驳回稿采用带状态条件的原子更新并递增版本，防止重复提交覆盖新状态。
- 编辑公开文章仍会暂时停止公开访问，直到再次审核通过；编辑页已提示。保存接口返回实际 status/content_version，前端不会对已处于 pending 的保存结果重复提交审核。

## 审核记录

迁移 005_post_review_versions 增加 posts.content_version、submitted_at、队列索引和 post_reviews。
审核记录保存文章 ID、内容版本、审核人 ID/名称、时间、结果、完整原因，以及当时的文章正文、封面 URL、媒体 URL、标签和游戏名称 JSON 快照。
审核记录、文章状态和站内通知在同一事务中提交；任一写入失败，全部回滚。同一文章版本只能产生一条审核结果。
记录不级联删除，保留已删除文章和账号的审核信息；通用操作日志仍作为辅助日志，不作为事务性证据。

限制：历史审核记录不回填；UI 仅展示当前文章最近 20 条记录摘要。JSON 快照不是图片/视频文件的永久归档，资源过期清理或人工删除后，旧媒体可能无法再次打开。完整媒体留存和全局历史检索属于后续功能。
